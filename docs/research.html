JobWall / research note 01

Resume as evidence, not a document to decorate.

Four real resumes, four different layouts, one pipeline. This paper shows what the parser actually recovers, what it has to infer, and where the refined dossier stops being trustworthy.

Abstract

The résumé builder is a reading problem first.

JobWall began as a way to turn a GitHub profile into a realistic job-title read. The résumé path reuses the same scorer, but the input is harder: a PDF has no paragraphs, only glyphs at coordinates; a DOCX has styles but no guarantee the author used them; and a two-column design can put two unrelated sections on the same baseline.

This note documents four public résumés taken through the current build: ingest, extract, normalize, score, and render one refined dossier. Every count, warning and role fit below comes from the parser and scorer at snapshot time. Nothing is hand-filled to make a case look better.

02 // extraction notes

  1. LaTeX PDF, one column, no skills section. Technologies live inside achievement prose, so the scorer has to infer them from sentences rather than a list.
  2. The employer line is bulleted above the job title. Without layout-aware pairing the parser saw four empty roles; the build now treats "Google Mountain View, CA" as the org/location seed for "Software Engineer".
  3. Project names are labels inside a single bullet ("QuantSoftware Toolkit : ..."), not headings. Those bullets now become named projects.
  4. The header puts the name and the email on the same physical line, and a bare domain ("sourabhbajaj.com") shares the next line with the phone label.

Findings

What broke, and what the build now does about it.

01 / tokenizer

A PDF operator written as TJ/F29 with no whitespace was read as one token. Names, employers and headings disappeared from extraction. Adding / as a delimiter fixed the case without a PDF library.

02 / headings

Real exports say “Experience”, not “EXPERIENCE”. Section detection now accepts a short title-case line that is exactly a section name, while still rejecting “Experience: 10 years”.

03 / org above title

“• Google Mountain View, CA” followed by “Software Engineer Oct 2016 – Present” is one role. The bullet now seeds the org and location instead of becoming an achievement.

04 / labeled bullets

“• QuantSoftware Toolkit : Open source…” is a project, not an unnamed bullet. The label becomes the name and the rest becomes the description.

05 / education

A bulleted school line followed by a dated degree line now merges into one entry with school, location, degree and dates.

06 / two columns

A split is only attempted when two section headings share a baseline on opposite sides of a gutter. Reading each column top-to-bottom recovers Deedy’s experience block.

07 / contact noise

Labels like “Email:” no longer become part of the name, and a bare domain such as sourabhbajaj.com is kept as a website.

08 / honesty

Warnings survive into the UI. The dossier says what it could not place instead of silently dropping lines to make the card look complete.

Two-column semanticsDeedy extracts, but links and coursework still land in education, and the org/title boundary is imperfect. Column geometry is not reading order.
